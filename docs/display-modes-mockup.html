mod_elediacheckin — Anzeige-Modi

Drei Darstellungsvarianten für eine Frage. Klick auf die Buttons wechselt zwischen den Mockups.

Modus 1: Normal — in die Kursseite eingebettet

Die übliche Moodle-Darstellung: Aktivität wird im Content-Bereich des Kurses angezeigt, Navigation, Header und Menüs bleiben sichtbar. Passt für Solo-Check-ins am eigenen Rechner.

Modus 2: Popup — separates Browserfenster

Ideal für Videokonferenzen mit Screensharing: das Popup-Fenster lässt sich einzeln teilen, ohne dass Moderator:innen die komplette Moodle-Oberfläche zeigen müssen. Das ursprüngliche Moodle-Fenster bleibt bestehen und kann Steuerbuttons anbieten.

Moodle Kursraum ▸ Check-in (Präsentationsmodus aktiv)

Check-in im Präsentationsmodus

Die Frage wird in einem separaten Fenster angezeigt. Hier steuerst du weiter.

moodle.example.com/mod/elediacheckin/present.php?id=42
Check-in · Energie

Auf einer Skala von 1 bis 10: Wie viel Energie bringst du heute mit?

Tipp: Das Popup ist technisch eine eigenständige URL (present.php?id=…) und funktioniert auch, wenn der Nutzer das Fenster auf einen zweiten Monitor zieht. Aktionen aus dem Moodle-Fenster (z.B. „Andere Frage") werden per BroadcastChannel / localStorage an das Popup gepusht.

Modus 3: Vollbild — gleiche Seite, alles überlagert

Ein Klick auf „Vollbild" legt ein Overlay über die ganze Seite. Keine Moodle-Navigation, keine Ablenkung, riesige Typografie, hoher Kontrast. Schließen-Button oben rechts.

Oder drücke Esc zum Schließen, sobald geöffnet.

Mod oder Block — wer darf was?

Empfehlung: Alle drei Modi leben im mod (dort ist die Darstellungslogik). Der block zeigt nur eine kompakte Karte im Dashboard und hat einen Button „Im Vollbild öffnen" bzw. „Als Popup öffnen", der den jeweiligen Endpoint des mod aufruft (present.php). Vorteil: eine einzige Implementierung, kein Code-Duplikat, der Block bleibt ein Entry-Point.
